# FINN — financial investment agent

FINN is a mobile-first prototype for monitoring a portfolio and researching NSE-listed companies. Its push view prioritizes filings and threshold alerts; its pull view searches annual reports and earnings-call transcripts and cites the retrieved document pages.

## Run locally

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
uvicorn main:app --host 0.0.0.0 --port 8000
```

Open [http://localhost:8000](http://localhost:8000). To use a phone on the same Wi-Fi, open `http://<your-computer-ip>:8000`.

Choose **Load demo data** for an offline walkthrough; demo filings and prices are synthetic and marked **DEMO**. The **Load live data** button remains available on the Today tab, including after demo data is loaded. It fetches Yahoo Finance prices and NSE announcements and reports the number of price rows and new filings, along with any per-symbol source failures. Public sources may rate-limit or change their response formats, so some symbols can fail.

## Deploy a public demo

The repository includes a Render Blueprint in `render.yaml`. Push the project to GitHub, then in Render choose **New → Blueprint**, connect that repository, and create the service. Add `LLM_KEY` as a secret in the Render service settings if you want generated summaries and research answers; the app can also run without it. After deployment, Render provides a public `https://…onrender.com` URL.

The free web service uses an ephemeral filesystem: SQLite data can be lost when the service restarts or redeploys. The fictional connected demo is generated by the app and does not depend on stored SQLite data. Live syncing and research ingestion are on demand. Do not put `.env`, API keys, the local database, or private chat exports in the public repository.

## Optional LLM setup

The app loads `.env` automatically. Set `LLM_KEY` to a key for an OpenAI-compatible provider, and adjust `LLM_BASE_URL`, `LLM_CHEAP`, and `LLM_STRONG` if needed. The defaults target Groq. Without a key, rules-based classification, scoring, prices, alerts, and retrieved research excerpts still work; generated filing summaries, headline-number extraction, and research answers are unavailable.

## What is included

- Portfolio digest with 24-hour, 3-day, 7-day, and 30-day windows; routine filings can be collapsed.
- Configurable volume, daily price-move, and announcement-category alerts.
- Filing links and optional headline-number extraction for results disclosures. QoQ and YoY changes are calculated in Python.
- On-demand research for any ticker, using screener.in documents or PDF URLs pasted in the Research tab. Retrieval uses page-level chunks and BM25 keyword ranking; answers are constrained to retrieved excerpts and include source citations.
- A connected, explicitly fictional Aster Mobility demo: guidance versus reported results, calculated Revenue/EBITDA/PBT/PAT QoQ and YoY, a synthetic price/volume move and sparkline, and a cited promised-versus-delivered research answer. Open **Today → Explore connected demo** or **Research → Try fictional demo**.
- SQLite persistence and prompt-response caching.

## Notes and limitations

- Live data requires internet access. NSE and screener.in may block automated requests, and filings are not continuously synchronized; use the buttons to refresh.
- PDF extraction depends on the PDF containing selectable text. Scanned documents may not yield usable excerpts.
- All demo-company names, prices, filings, figures, and source excerpts are fictional illustrations and must not be used for investment decisions.
- The prototype does not include authentication, scheduled syncing, embeddings, LinkedIn biographies, or financial-statement quality modules.

The SQLite database is created as `finn.db` beside `main.py`. Set `FINN_DB_PATH` to use another location.
